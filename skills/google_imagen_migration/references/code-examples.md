# Call shapes — Imagen 4 versus Gemini native image generation

Both excerpts are reduced from the pinned Egaki baseline
(`amelia751/egaki` @ `c09e1a44200ff5e951746e013035e68aeb3a14b1`,
`cli/src/cli/generate.ts` and `cli/src/cli/model-catalog.ts`). They are here to
show why the two surfaces are not interchangeable, not to be pasted into a patch:
the shape a given repository uses is whatever its own dispatch does.

## Catalog entry — the strategy is the load-bearing field

```ts
const googleImagen = {
  provider: 'google',
  strategy: 'image' as const,
  features: {
    editing: true,
    inpainting: true,
    aspectRatios: ['1:1', '3:4', '4:3', '9:16', '16:9'],
    seed: true,
    multipleImages: true,
  },
}

const googleText = {
  provider: 'google',
  strategy: 'text' as const,
  features: {
    editing: true,
    inpainting: false,
    aspectRatios: ['1:1', '3:4', '4:3', '9:16', '16:9', '2:3', '3:2', '4:5', '5:4'],
    seed: false,
    multipleImages: false,
  },
}
```

Rewriting an entry's `id` to a Gemini model while it still spreads
`...googleImagen` leaves `strategy: 'image'`, which sends a Gemini model down a
request path it does not implement. The identifier is the visible part of the
change; the strategy is the actual one.

## Dispatch — where the option set is decided

```ts
if (config.strategy === 'image') {
  return generateWithImageModel({
    prompt, model, count, aspectRatio, seed, inputImages, maskImage,
    allowPeople, quality, resolution, outputFormat, negativePrompt,
  })
}

// Text model path (Gemini multimodal)
return generateWithTextModelPath({
  prompt, model, inputImages, imageSize, aspectRatio,
})
```

Nine arguments on one branch, five on the other. Every argument that does not
cross the branch is a capability the caller loses — and a compiler that is
perfectly happy about it, because the two functions have different signatures and
the caller simply stops passing the extras.

## The Gemini image request

```ts
const result = await generateText({
  model: textModel,
  ...(messages ? { messages } : { prompt }),
  providerOptions: {
    google: {
      responseModalities: ['TEXT', 'IMAGE'],
      imageConfig: { imageSize, aspectRatio },
    },
  },
})

const imageFiles = result.files.filter((f) => f.mediaType.startsWith('image/'))
if (imageFiles.length === 0) {
  return new Error('No images generated by the text model.')
}
```

Notes that matter for a migration:

- Image bytes arrive as response *files*, not as the return value of an image
  call. Any caller that assumed the image-model return shape needs its handling
  changed, not just its model string.
- `imageConfig.imageSize` takes `'1K' | '2K' | '4K'`. It is the nearest analogue
  to the image path's `resolution`, in a different value space — a human
  decision, not a rename.
- There is no `seed`, no count, no mask, no negative prompt on this path. Dropping
  them compiles, passes tests, and changes behaviour. That is why the capability
  map escalates each one.
- Provider routing is a separate axis: the same code selects the `vertex` or
  `google` provider options key. A migration must cover both routes.
